# Frontend Rules

## Tooling

- **Prettier** for formatting — config: `frontend/.prettierrc`
- **ESLint** for linting — config: `frontend/eslint.config.ts`
- TypeScript strict mode is on — no `any`, no `@ts-ignore`
- Run before committing: `yarn format && yarn lint`

## Component Patterns

**Arrow function components for all `.tsx` files:**

```tsx
// ✅ correct
const UserCard: React.FC<Props> = ({ name }) => {
  return <div>{name}</div>
}
export default UserCard

// ❌ wrong — function declaration in a component file
export default function UserCard({ name }: Props) { ... }
```

**Named function exports for `.ts` utility files:**

```ts
// ✅ correct
export function formatHex(value: string): string {
  return value.startsWith('#') ? value : `#${value}`
}

// ❌ wrong — arrow function as default export in a .ts util file
export default (value: string) => `#${value}`
```

Never use class components.

## File Organization

```
frontend/src/
├── routes/           ← TanStack Router pages; one file per route
├── components/       ← Grouped by feature, then shared/
│   ├── converter/
│   ├── calibration/
│   ├── extractor/
│   └── shared/       ← Reusable primitives (Button, Modal, JobProgress, etc.)
├── hooks/            ← All custom hooks; API hooks live here
├── api/
│   └── generated/    ← Auto-generated by openapi-ts; never edit manually
├── stores/           ← Zustand stores only
├── i18n/             ← i18next config and init only (no translation strings here)
├── styles/           ← Global SCSS (_variables.scss, _reset.scss, _typography.scss)
└── types/            ← Hand-written TypeScript types not covered by OpenAPI
```

## Styling Rules

- Every component has a co-located `.module.scss` file — no exceptions
- **Never use the `style` prop** — ESLint will error on this
- **MUI `sx` prop only for runtime-dynamic values** (e.g. a hex color from state); static styles go in SCSS
- **Maximum 3 levels of nesting** in any SCSS block:

```scss
// ✅ correct
.card {
  .header {
    .title { font-size: 1.2rem; }
  }
}

// ❌ wrong — 4th level
.card {
  .header {
    .title {
      span { ... }  // too deep — flatten or extract a new class
    }
  }
}
```

- Use variables from `src/styles/_variables.scss` for spacing, colors, and breakpoints
- Class naming inside modules: `.block`, `.block__element`, `.block--modifier`

## API Hook Pattern

Never call generated services or Axios directly from a component.
All API calls are wrapped in custom hooks in `hooks/`:

```ts
// hooks/useLutList.ts
import { useQuery } from '@tanstack/react-query'
import { LutService } from '../api/generated/services.gen'

export const useLutList = () =>
  useQuery({
    queryKey: ['lut', 'list'],
    queryFn: () => LutService.list(),
  })
```

```ts
// hooks/useGeneratePreview.ts
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { ConverterService } from '../api/generated/services.gen'

export const useGeneratePreview = () => {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: ConverterService.generatePreview,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['preview'] }),
  })
}
```

**Job polling:**

```ts
// hooks/useJobPoller.ts
export const useJobPoller = (jobId: string | null) =>
  useQuery({
    queryKey: ['job', jobId],
    queryFn: () => JobService.getStatus(jobId!),
    enabled: !!jobId,
    refetchInterval: (query) =>
      query.state.data?.status === 'done' || query.state.data?.status === 'error'
        ? false
        : 1000,
  })
```

Components import hooks only — never services:

```tsx
// ✅ correct
import { useLutList } from '../hooks/useLutList'

// ❌ wrong
import { LutService } from '../api/generated/services.gen'
```

## State Ownership

| State type | Tool |
|------------|------|
| Server data (API responses, job results) | TanStack React Query |
| UI-only state (replacement history, selected color, lang) | Zustand |
| Local component state (open/close, draft input values) | `useState` |

Never duplicate server state in Zustand.

## Import Order

1. React and React ecosystem
2. Third-party libraries (MUI, Three.js, Zustand, etc.)
3. Generated API types/services (`../api/generated/`)
4. Internal hooks, stores, components
5. Types (`type` imports)
6. SCSS module (always last)
