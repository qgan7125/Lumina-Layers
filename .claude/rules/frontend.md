# Frontend Rules

## Tooling

- **Prettier** for formatting — config: `frontend/.prettierrc`
- **ESLint** for linting — config: `frontend/eslint.config.ts`
- TypeScript strict mode is on — no `any`, no `@ts-ignore`
- Run before committing: `yarn format && yarn lint`

## Component Patterns

**Arrow function components for all `.tsx` files:**

```tsx
// ✅ correct — reusable component (default export)
const UserCard: React.FC<Props> = ({ name }) => {
  return <div>{name}</div>
}
export default UserCard

// ✅ correct — route-level tab component (named export)
const SettingsTab: React.FC = () => { ... }
export { SettingsTab }

// ❌ wrong — function declaration
export default function UserCard({ name }: Props) { ... }
```

**Named function exports for `.ts` utility and hook files:**

```ts
// ✅ correct
export function formatHex(value: string): string {
  return value.startsWith('#') ? value : `#${value}`
}

// ❌ wrong — arrow function as default export in a .ts util file
export default (value: string) => `#${value}`
```

Never use class components.

## Feature Component Structure

Every feature component is a self-contained folder with exactly three files.
Reference implementation: `frontend/src/components/LUT/`

```
frontend/src/components/{Feature}/
├── {Feature}.tsx           ← arrow function component, export default
├── {Feature}.module.scss   ← co-located styles
└── hooks/
    └── use{Feature}.ts     ← named function, combines all related queries + mutations
```

Use `/new-component <FeatureName>` to scaffold this structure.

**Co-located hook rules:**
- Named function export: `export function use{Feature}() { ... }`
- Combines all related `useQuery` and `useMutation` for this feature into one function
- Imports from `'../../../api/generated'` — never from `services.gen`
- Returns a flat object: `{ data, isLoading, mutateAsync, isPending, ... }`
- Invalidates related query keys `onSuccess` where needed

```ts
// ✅ correct — components/LUT/hooks/useLut.ts
export function useLut() {
  const queryClient = useQueryClient()
  const { data: lutList, isLoading } = useQuery({
    queryKey: ['lut', 'list'],
    queryFn: () => listLutsApiLutListGet({ throwOnError: true }).then((r) => r.data),
  })
  const { mutateAsync: updateLutFile, isPending: isUploadLutPending } = useMutation({
    mutationFn: (file: File) =>
      uploadLutApiLutUploadPost({ body: { file }, throwOnError: true }).then((r) => r.data),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['lut', 'list'] }),
  })
  return { lutList, isLoading, updateLutFile, isUploadLutPending }
}
```

## File Organization

```
frontend/src/
├── routes/           ← TanStack Router pages; one file per route
├── components/       ← One folder per feature; each is self-contained
│   ├── LUT/          ← {Feature}.tsx + {Feature}.module.scss + hooks/use{Feature}.ts
│   ├── FileUpload/   ← Shared primitive — use for ALL file inputs
│   ├── Notification/ ← Shared primitive — use useNotify() for ALL feedback
│   └── ...
├── hooks/            ← Cross-component hooks only (e.g. useConverterJobStatus)
├── api/
│   └── generated/    ← Auto-generated by openapi-ts; never edit manually
├── stores/           ← Zustand stores only
├── i18n/             ← i18next config and init only (no translation strings here)
├── styles/           ← Global SCSS (_variables.scss, _reset.scss, _typography.scss)
└── types/            ← Hand-written TypeScript types not covered by OpenAPI

public/
└── locales/          ← Translation files loaded at runtime via i18next HTTP backend
    ├── zh/
    │   └── translation.json
    └── en/
        └── translation.json
```

**Hook location rule:**
- Feature-specific hooks → `components/{Feature}/hooks/use{Feature}.ts`
- Hooks shared across multiple components → `src/hooks/`

## Styling Rules

- Every component has a co-located `.module.scss` file — no exceptions
- **Never use the `style` prop** — ESLint will error on this
- **MUI `sx` prop only for runtime-dynamic values** (e.g. a hex color from state); static styles go in SCSS
- **Maximum 3 levels of nesting** in any SCSS block:

```scss
// ✅ correct
.card {
  .header {
    .title { font-size: 1.2rem; }
  }
}

// ❌ wrong — 4th level
.card {
  .header {
    .title {
      span { ... }  // too deep — flatten or extract a new class
    }
  }
}
```

- Use variables from `src/styles/_variables.scss` for spacing, colors, and breakpoints
- Import with `@use 'variables' as *;` — `loadPaths: ['src/styles']` is set in `vite.config.ts`, no relative path needed
- Class naming inside modules: `.block`, `.block__element`, `.block--modifier`

## API Hook Pattern

Never call generated API functions or Axios directly from a component.
All API calls go through custom hooks.

**Import from the generated barrel — never from `services.gen` (doesn't exist):**

```ts
// ✅ correct
import { listLutsApiLutListGet } from '../../../api/generated'

// ❌ wrong
import { LutService } from '../api/generated/services.gen'
```

**Job polling pattern (used in cross-component hooks in `src/hooks/`):**

```ts
// src/hooks/useExtractJobStatus.ts
export const useExtractJobStatus = (jobId: string | null) =>
  useQuery({
    queryKey: ['extractor', 'job', jobId],
    queryFn: () =>
      jobStatusApiExtractorJobStatusJobIdGet({ path: { job_id: jobId! }, throwOnError: true })
        .then((r) => r.data),
    enabled: !!jobId,
    refetchInterval: (query) =>
      query.state.data?.status === 'done' || query.state.data?.status === 'error'
        ? false
        : 1000,
  })
```

**User feedback — always `useNotify()`, never local `<Snackbar>` state:**

```tsx
// ✅ correct
const notify = useNotify()
try {
  await mutateAsync(file)
  notify(t('upload_success'), { severity: 'success' })
} catch {
  notify(t('upload_error'), { severity: 'error' })
}

// ❌ wrong
const [snackbar, setSnackbar] = useState<string | null>(null)
// ...
<Snackbar open={!!snackbar} message={snackbar} ... />
```

**File inputs — always `<FileUpload>`, never `<input type="file">`:**

```tsx
// ✅ correct
<FileUpload
  variant="dropzone"
  accept={['image/*']}
  loading={upload.isPending}
  onFiles={handleFiles}
/>

// ❌ wrong
<Box component="label"><input type="file" accept="image/*" hidden /></Box>
```

## State Ownership

| State type | Tool |
|------------|------|
| Server data (API responses, job results) | TanStack React Query |
| UI-only state (replacement history, selected color, lang) | Zustand |
| Local component state (open/close, draft input values) | `useState` |

Never duplicate server state in Zustand.

## Import Order

1. React and React ecosystem (`react`, `react-i18next`)
2. MUI components (`@mui/material/...`)
3. MUI icons (`@mui/icons-material/...`)
4. Other third-party libraries (Three.js, Zustand, etc.)
5. Internal: hooks, stores, shared components
6. Type-only imports (`type` keyword)
7. SCSS module (always last)
